# Wa-Catalog Project Agents Documentation

This document provides an overview of the Wa-Catalog project, its components, and how to interact with it using various agents (subagents) for development, deployment, and maintenance.

## Project Overview

Wa-Catalog is an e-commerce store built with Astro that integrates with WhatsApp for ordering. It features:
- Product catalog with categories
- Shopping cart that redirects to WhatsApp for order submission
- Admin interface via DecapCMS for managing products and categories
- Bot interface (WhatsApp/Telegram) for quickly adding products via chat
- Automatic deployment via GitHub Actions upon content changes

## Key Components

### 1. Astro Frontend (`/src`)
- **Pages**: 
  - Home (`src/pages/index.astro`)
  - Product listing by category (`src/pages/categories/[category].astro`)
  - Product detail (`src/pages/products/[id].astro`)
  - VIP routes (`src/pages/vip/[vipcode]/...`) for accessing VIP products
  - Admin (`src/pages/admin/index.astro`) - loads DecapCMS
- **Layouts**: 
  - Base layout (`src/pages/layouts/_Layout.astro`)
  - Home layout (`src/pages/layouts/HomeLayout.astro`)
  - Product layout (`src/pages/layouts/ProductLayout.astro`)
- **Components**: Reusable UI elements (header, footer, product cards, etc.)
- **Styling**: Tailwind CSS with custom color palette (primary, accent, sand)
- **Data Layer**:
  - Categories: `src/data/categories.json` (static JSON)
  - Products: Individual JSON files in `src/data/products/` (synced from GitHub repo)
  - Utilities: 
    - `src/lib/products.ts` - loads products from JSON files
    - `src/lib/categories.ts` - processes category data
    - `src/utils/helpers.ts` - exposes environment variables and helper functions
    - `src/schemas/index.ts` - Zod schema for product validation

### 2. Bot (`/bot`)
A WhatsApp/Telegram bot that allows administrators to add products by sending messages.
- **Packages**:
  - `bot/packages/core`: Contains the bot engine (`BotEngine`), state machine (`StateMachine`), and GitHub service (`GitHubService`)
  - `bot/packages/whatsapp`: WhatsApp adapter
  - `bot/packages/telegram`: Telegram adapter
  - `bot/packages/types`: Shared TypeScript interfaces
- **Functionality**:
  - Receives messages (text, images) from authorized users
  - Guides user through product creation steps (title, price, currency, description)
  - Commits product data as JSON to `src/data/products/<id>.json` in the GitHub repo
  - Uploads images to `public/images/<id><ext>`
  - Triggers automatic redeploy via GitHub Actions push

### 3. DecapCMS Admin (`/src/pages/admin`)
- **Interface**: Accessible at `/admin` after authentication
- **Configuration**: Dynamically generated by `src/pages/admin/config.yml.ts`
  - Uses Decap Bridge for authentication (PKCE flow)
  - Manages:
    - `products` collection: Edits JSON files in `src/data/products/`
    - `config` collection: Edits `src/data/categories.json`
  - Supports image uploads to `public/images/`
  - Commits changes directly to the GitHub repo, triggering redeploy

### 4. Deployment (GitHub Actions)
Workflows in `.github/workflows/`:
- `deploy-github.yml`: Deploys to GitHub Pages (triggered on push to `root/main` and `root/data`)
- `deploy-caprover.yml`: For CapRover deployments
- `deploy-infinityfree.yml`: For InfinityFree deployments
- **Process**:
  1. Checkout repository
  2. Create `.env` from secrets/variables
  3. Install dependencies (`pnpm install`)
  4. Build site (`pnpm build`)
  5. Deploy output to specified platform

## Environment Variables
Defined in `.env` (not committed) and referenced in `.env.example`:
- `PUBLIC_WHATSAPP_NUMBER`: WhatsApp number for contact button
- `PUBLIC_APP_NAME`: Store name (shown in footer)
- `PUBLIC_APP_VIP_CODE`: Code for accessing VIP routes (e.g., `gitana`)
- `PUBLIC_APP_DESC`: Store description (footer)
- `PUBLIC_BANNER_TITLE`: Hero banner title
- `PUBLIC_BANNER_CONTENT`: Hero banner content
- `PUBLIC_STORE_LOCATION`: Physical store location (footer)
- `PUBLIC_STORE_HOURS`: Store hours (footer)
- `PUBLIC_SITE`: Production site URL (optional)
- `PUBLIC_BASE_URL`: Base path for deployment (e.g., for GitHub Pages)
- `PUBLIC_DECAPBRIDGE_ID`: Decap Bridge site ID for admin authentication
- `PUBLIC_REPO`: GitHub repo (owner/repo) for bot and CMS
- `PUBLIC_REPO_BRANCH`: Branch where content is stored (e.g., `root/data`)

## Local Development
1. Install dependencies: `pnpm install`
2. Start development server: `pnpm dev` (runs at `http://localhost:4321`)
3. Access admin: `http://localhost:4321/admin` (requires Decap Bridge setup)
4. To run the bot:
   - Navigate to `bot/` directory
   - Install: `pnpm install`
   - Start: `pnpm start` (or check `bot/package.json` for start script)
   - Ensure you have set required environment variables (GitHub token, repo, branch, etc.)

## Managing Products
### Via DecapCMS (Web Interface)
1. Visit `/admin` and authenticate with GitHub (via Decap Bridge)
2. Navigate to "Products" collection
3. Click "New product" to create or select an existing product to edit
4. Fill in form fields (name, price, featured/vip/available flags, description, images, categories)
5. Save - DecapCMS commits directly to GitHub, triggering redeploy

### Via Bot (WhatsApp/Telegram)
1. Send a message to the bot's number (must be authorized)
2. Follow prompts:
   - Send product photo (optional but recommended)
   - Provide product title/name
   - Provide price (in CUP)
   - Confirm currency (default CUP)
   - Provide description (or skip)
3. Bot commits product and image to GitHub, triggering redeploy

## VIP Access
- Routes under `/vip/<code>/...` are restricted to the value of `PUBLIC_APP_VIP_CODE`
- VIP products (those with `"vip": true` in their JSON) are only accessible via these routes
- Non-VIP products are accessible via regular routes (`/products/...`, `/categories/...`)

## Extending the Project
### Adding New Data Collections to DecapCMS
1. Edit `src/pages/admin/config.yml.ts`
2. Add a new collection definition under `collections:`
3. Specify folder, fields, and widget types
4. Restart dev server or rebuild for changes to take effect

### Modifying Bot Behavior
1. Edit files in `bot/packages/core/src/`
   - `state-machine.ts`: Adjust conversation flow
   - `github.ts`: Modify GitHub commit logic
   - `extractor.ts`: Change how product data is parsed from text
2. Rebuild bot if necessary: `cd bot && pnpm install`

### Changing Styling or Layout
1. Modify Tailwind configuration: `tailwind.config.mjs`
2. Edit Astro components in `/src/components/` and `/src/layouts/`
3. Update styles in `/src/styles/` if applicable

## Troubleshooting
- **Admin not loading**: Check `PUBLIC_DECAPBRIDGE_ID`, `PUBLIC_REPO`, `PUBLIC_REPO_BRANCH` in `.env`
- **Bot not responding**: 
  - Verify bot process is running
  - Check WhatsApp/Telegram adapter logs
  - Ensure GitHub token has `repo` scope
  - Confirm `PUBLIC_REPO` and `PUBLIC_REPO_BRANCH` are correct
- **Deployment failing**: 
  - Check GitHub Actions logs
  - Verify `.env` secrets are set in repository settings
  - Ensure `pnpm build` works locally
- **Products not showing**: 
  - Run `pnpm build` locally to see if there are build errors
  - Check that product JSON files are valid (conform to schema)
  - Ensure products have `"available": true`
